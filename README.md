# ボードゲームひろば（仮）

ボードゲームを日本の"ふつうの遊び"に定着させるための Web アプリ。
**インスト（ルール説明）・場所・認知**の3つのハードルを下げる「ハブ」を目指す。

> このリポジトリの**現行アプリは `hub/`** です。ルート直下の `yomite.tsx` は、
> このコンセプトの元になった初期プロトタイプ（Claude チャットのアーティファクト）で、
> `HANDOFF.md` / `PWA SETUP.md` はその頃の引き継ぎ資料（**レガシー**）です。
> 現行アプリの仕様はこの README を参照してください。

---

## いま作られているもの（`hub/`）

トップに3つの扉：

| 扉 | 役割 | 状態 |
|---|---|---|
| **教わる／教える** `/learn` | インスト台本の作成・共有＋早見表 | ✅ 実装済み |
| **集まる** `/place` | 場所・卓・相手のマッチング | ⬜ プレースホルダー |
| **出会う** `/discover` | 診断でおすすめゲーム紹介 | ⬜ プレースホルダー（設計済み） |

### 教わる／教える（実装済みの中身）

- **インスト台本**：全10セクション（①どんなゲーム ②勝利条件 ③準備 ④流れ ⑤手番でできること
  ⑥得点 ⑦終了条件 ⑧アイコン早見表 ⑨特殊ルール ⑩よくある勘違い）。テーマ別タブで表示。
- **早見表（サマリー）の自動生成**：台本の⑤⑦⑧から「卓に置く1枚」を生成。表裏・**印刷/PDF**対応。
- **ゲームのカタログ**：表紙（色＋絵文字）・人数・時間・システム（12種）。
  検索／人数（複数選択）／ジャンル／並び（新着・人気）で絞り込み。
  ゲーム選択 →（台本が複数あれば）どの台本かを選ぶ → 台本詳細、の導線。
- **アカウント（任意ログイン）**：閲覧は誰でも可。**いいね・投稿・編集はログイン必須**。
  台本作成・サマリー作成は**最終的に有料プラン**の想定（現状は仮の PRO フラグ）。
- **プロフィール** `/u/:handle`（X風・作った台本／いいね）、**いいね❤️**、作者表示。
- 収録済みの運営台本：宝石の煌めき／ドミニオン／カルカソンヌ／ストーンエイジ／
  チケット・トゥ・ライド 等（アイコンは絵文字＝出版社画像は不使用）。

## 動かし方

```bash
# バックエンド（サマリー/台本の共有API）
cd hub/server
npm install
npm start          # http://localhost:8787

# 別ターミナルでフロント（Vite が /api をサーバーへプロキシ）
cd hub
npm install
npm run dev        # http://localhost:5173
```

### 触れるデモ（1ファイルに固める）

```bash
cd hub
VITE_DEMO=1 npm run build   # HashRouter＋localStorage 保存・全部を1つのHTMLに
```

`VITE_DEMO=1` のときはサーバー不要（保存はブラウザ内 localStorage、ルーティングはハッシュ）。

## 構成

```
hub/
  src/
    App.jsx            # ルーティング＋アカウント（任意ログイン）
    pages/             # Home / Learn / Place / Discover / Profile / AuthGate
    script/            # 台本：ScriptBuilder, ScriptCard, GameTile, model, sections,
                       #       mechanics, samples, store
    summary/           # 早見表：SummaryCard, IconPicker, model, icons
    social/            # auth, AuthContext, likes, LikeButton
    styles.css         # デザイン（:root のトークンで一括調整）
  server/              # Express + JSON保存（db.js に隔離＝後でDBに差し替え可能）
yomite.tsx             # 初期プロトタイプ（レガシー・参考）
HANDOFF.md / PWA SETUP.md  # 旧ヨミテの引き継ぎ資料（レガシー）
```

## 既知の制約（本番化で対応すべき点）

現状は**プロトタイプ／デモ仕様**。以下は本番化フェーズで対応する：

- **認証・認可がデモ仕様**：ログインはハンドル入力のみ（パスワード無し・端末内保存）。
  サーバー API に認可が無く、作者名は自己申告。→ 本番は Supabase 等の認証＋所有者チェック（RLS）へ。
- **いいねが端末ローカル**：`localStorage` 保存で他ユーザーと共有されない。→ DB のリレーションへ。
- **保存が単一 JSON ファイル**：`hub/server/db.js`。並行書き込み・スケールに弱い。→ Postgres 等へ。
- ゲームのグルーピングがタイトル文字列一致（表記ゆれに弱い）。→ ゲームIDに正規化予定。

`db.js` / `store.js` / `social/auth.js` は差し替えしやすいよう分離してある。
