# ボードゲームひろば（仮）— 開発メモ

React 18 + Vite 5 + React Router 6 のボードゲーム「ハブ」アプリ。3つの扉
（教わる `/learn`・集まる `/place`・出会う `/discover`）で、インスト／場所／認知の
ハードルを下げることを狙う。公式の「インスト台本」は `src/script/samples.js`
（`SAMPLE_SCRIPTS`）に置く。台本は10セクション構成（`src/script/sections.js`）で、
早見表（サマリー）は台本から自動生成される。

## 台本作成のワークフロー（必須）

**新しいボードゲームの台本を考える・追加する・大きく直すときは、必ず次の2人の
サブエージェントを動かして添削させてから反映する。** これはユーザーの明確な指示。
片方だけで済ませない。両者の指摘を突き合わせてから `samples.js` に反映する。

### レビュアー1：文章校正・校閲のプロ
- ボードゲームの知識は前提にせず、**文章としての質**だけを審査する。
- 観点：**重複**（同じ情報が複数セクションに散っていないか）、**順番・構成**、
  表記ゆれ（例：名声/威信ポイント、周/ラウンド、宝石トークン/トークン）、
  冗長表現、強調記号（“　”）の乱用、読みやすさ。
- ルールの正誤は判断させない。
- 出力：重複マップ／順番の指摘／表記・文体の指摘／各セクションの推奨リライト。

### レビュアー2：インスト経験者（ボードゲーム理解者）
- 普段からゲーム会で初心者にインストしている経験者の立場。
- 観点：**(A) ルールの正確さ**（トークン枚数・終了/同点処理・例外の扱い等）、
  **(B) 卓上で教えるときの順番・分かりやすさ**、**(C) インストとしての過不足**
  （初心者が実際に詰まる点／初回には不要で省ける点）。
- 出力：ルールの正誤（正しければ「正しい」と明記）／推奨する説明順序／重複の指摘／
  過不足／各セクションの推奨リライト。

### 進め方
1. 対象の台本（10セクション）を全文テキストにして、両エージェントへ同じ内容を渡す。
2. どちらも「ファイルは編集しない。指摘とリライト案をテキストで返すだけ」と指示。
3. 2人の指摘を突き合わせ、こちら（メイン）で最終形を決めて `samples.js` を編集する。
   一本化先の優先度（どのセクションを正典にするか）は自分で決めてよい。
4. `VITE_DEMO=1 npm run build` → `dist/artifact.html` を再生成 → 同じ Artifact URL に
   publish → Playwright で全タブ＋早見表を確認 → コミット＆プッシュ。

宝石の煌めき（`id: "splendor"`）が、この2人の添削を通した「品質の基準」。
新しい台本はこの粒度（正確・重複なし・教えやすい順番）に合わせる。

## デモ／確認の定型
- デモ用ビルド：`VITE_DEMO=1 npm run build`（HashRouter + localStorage + singlefile）。
  そのあと `dist/index.html` から `<style>`・`<script>` を取り出して `dist/artifact.html`
  を作り、固定 Artifact URL に publish する。
- Playwright は `/opt/node22/lib/node_modules/playwright` を
  `import pw from '...'; const { chromium } = pw;` で使う。
- 台本を個別に開く動線：`/#/learn?script=<id>`（`/game/:id` の紹介ページからも直行）。
